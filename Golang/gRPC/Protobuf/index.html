【gRPC】Protocol Buffers

发表于 2026-07-16 分类于 Golang ， gRPC 阅读次数：
本文字数： 4.2k 阅读时长 ≈ 8 分钟
protocol buffers简单入门，可以用于快速生成结构化数据

用处

Protocol Buffers用于序列化结构化数据，它类似于JSON，但是更小更快，和语言、平台无关

在一个微服务中，若有不同语言想要使用该服务，调用对应API接口，但是由于语言不同，为了支持其他语言，我们需要开发第三方library才能支持

Protobuf解决了这种问题，只需要一个.proto文件定义数据类型与结构或API接口，自带的编译器就可以根据该文件自动生成对应语言的代码

快速上手

编写

  • 首先声明使用的proto版本以及该文件下的命名空间
  • 使用import导入外部包
  • 通过option go_package声明生成的.pb.go文件声明在哪个go包下，导入路径是什么
  • 接下来定义自己的消息（message），除了基本类型，还可以在message中定义message，或定义枚举
  • 若一个字段是repeated，则该字段可以重复任意次数，可以看作动态大小的数组
  • 若一个字段是map，则该字段是一个键值对类型
  • 每个元素的=1等标记标识了该字段在二进制编码中使用的唯一标签，不可以重复使用，从1开始，1-15比其他数字少用一个字节编码，因此可以作为常用或repeated类型的字段，16以上用于不常用的字段
  • 字段编号 19,000 到 19,999 为 Protocol Buffers 实现保留。

扩展protocal buffer

如果想要更新或扩展proto文件，且让新旧缓冲区前后兼容，需要遵循如下规则：

  • 绝对不可以更改现有字段的标签号
  • 可以删除字段
  • 可以添加新字段，但必须使用新的标签号（被删除字段用过的也不行）
  • 新字段在旧消息中是不存在的，需要处理默认值，默认的默认值为：对于字符串，默认值是空字符串。对于布尔值，默认值是 false。对于数字类型，默认值是零

语法

字段默认值

当解析消息时，如果编码的消息字节中不包含某个特定字段，那么在解析的对象中访问该字段将返回该字段的默认值。默认值是类型特定的：

  • 对于字符串，默认值是空字符串

  • 对于字节，默认值是空字节

  • 对于布尔值，默认值是 false

  • 对于数值类型，默认值是零。

  • 对于消息字段，该字段未设置。其确切值取决于语言

    对于枚举，默认值是第一个定义的枚举值，它必须为 0

对于 repeated 字段，默认值是空的（通常是相应语言中的空列表）

对于 map 字段，默认值是空的（通常是相应语言中的空 map）

枚举

在protobuf文件中使用enum定义枚举

枚举值前缀

枚举值添加前缀时，剥离前缀后的其余名称仍应该是合法且符合样式的枚举名，如DEVICE_TIER_1是不对的，应该使用类似DEVICE_TIER_TIER1，因为前缀部分会被视为对枚举值进行作用域限定，而不是作为单个枚举值名称的一部分

枚举默认值

proto3中，枚举定义中定义的第一个值必须为0，且不具有语义含义

如CORPUS_UNSPECIFIED = 0;

这样方便我们将0作为数字默认值

序列化与反序列化

Go中可以使用proto库中的函数来序列化和反序列化protocol buffer数据

proto的结构体均默认实现了proto.Message接口，需要传递操作指针

序列化

  • 首先创建指针类型的变量，添加数据
  • proto.Marshal(book)会将这个结构体按照protobuf的二进制格式编码为一串字节
  • 这样out里就算可以保存的二进制数据
  • 这样就可以使用WriteFile()写入文件

反序列化

  • 首先通过ReadFile()读取文件
  • 准备一个空的结构体指针，用来接收数据
  • 使用proto.Unmarshal()将字节反解成protobuf数据，填充到结构体中

保留字段

对于删除或注释掉的字段，更好的方法是使用reserved，reserved之后的字段编号会被标记为保留，若使用这些编号会报错

同理字段名也可以被保留

注意：不能在同一个语句中混合字段名和字段编号

映射

定义映射的语法：map<key_type, value_type> map_field = N;

其中key_type可以是任何整数或字符串类型，value_type可以是除另一个map之外的任何类型

注意：

  • map字段不能是repeated
  • 映射值的线路格式顺序和映射迭代顺序是未定义的，所以你不能依赖你的映射项会以特定的顺序排列
  • proto生成文本格式时，映射按键排序，数字键按值排序
